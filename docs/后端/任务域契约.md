# 任务域契约（P3e 规范化记录）

> 以既定契约为基线：task / workspace / 分组子路由（FastAPI 参考实现）。
> 实现见 `cineforge-server/internal/api/task_handlers.go`、`internal/service/tasks.go`、`internal/repository/{tasks,tasks_read,tasks_batch,tasks_prompt,tasks_grouping,tasks_submission}.go`。
> 契约测试见 `internal/api/task_contract_test.go`（全部通过）。
> 错误映射：`KeyError→404`、`PermissionError→403`、`ValueError→400`、`HTTPException` detail 逐字透传（对照既定路由层对齐 `PermissionError→403 detail` 与 `KeyError→404 detail`）。
> 事务：所有写路径 `service.withTx` 开 `pgx.Tx` → repository 变更函数收 `pgx.Tx`（不自行 commit/rollback）→ 提交；提交后在连接池重读任务视图返回。

## 权限模型（重要）

项目级任务读取对齐既定契约 `_can_access_project`，判定顺序固定：

1. 项目存在性（404 `Project not found` 优先）；
2. director/admin → 放行；
3. 有 `project_role:%` 权限行 → 放行；
4. 项目内有「可见任务」（assignee 且非 completed/未过期，`variant_plan_id IS NULL` 且资产未删除/排除）→ 放行；
5. 否则 403 `Project permission denied`。

- 实现：service `GetProjectForTask` / `ProjectService.canRead`；repository `Tasks.CanAccessProject`（含第 4 档回退，仓库内部防御与 service 一致）。
- 权限放行 ≠ 数据可见：storyboards / board / scene-gating 对非导演仍按「可见任务」过滤到自己的责任范围（对齐 `_visible_task_stmt` / `_visible_storyboard_ids_for_project`）。
- 任务级读取（GET/PATCH /tasks/{id}）：导演/admin、任务 assignee、或项目角色 → 放行；否则 403（对齐既定契约 `get_task`，assignee 自身恒可读自己的任务）。

## 任务列表 / 详情 / 更新

### GET /api/tasks

- 过滤 query：`project_id`、`status`（枚举外 → 422 `请求体格式错误`）、`assignee_id`。
- 可见性：非导演/admin 按 `visibleTaskWhere`（项目角色 ∪ assignee 可见任务），返回 `TaskView[]`。

### GET /api/tasks/{task_id}

- 404 `task not found`（不存在或资产已删除/排除）；403（无权限，既定契约文案对齐）。
- 返回 `TaskView`（56 字段，含 assignee、submissions、batches、依赖结构、场景锁等）。

### PATCH /api/tasks/{task_id}

- 字段：`status`（枚举外 → 422 `请求体格式错误`）、`prompt_text`、`due_at`、`assignee_id`（改派，必须带原因）、`production_model`/`media_type`/`scene_code`/`scene_name`/`title`/`description` 等。
- 非 director 改 `status` → 403。
- 守卫（detail 逐字）：
  - `待审核或已完成任务不能改派执行人。`
  - `改派任务必须填写改派原因。`
  - 改为 completed 但无 primary master → `任务必须先完成成果审核并指定主母版。`
- 改派触发通知：`收到改派任务` / `任务已改派`，正文 `{旧执行人} 已改派给你。改派原因：{原因}` / `{原执行人} 已改派给 {新执行人}。改派原因：{原因}`。

## 任务提示词

### GET/POST /api/tasks/{task_id}/prompts

- 列表 `TaskPrompt[]`；POST 建提示词（201，`agent_run_id` 可空、`manual` 可空等默认字段对齐既定契约）。
- 守卫（detail 逐字）：
  - 前置/依赖未满足：`{前置步骤} 尚未完成，当前任务暂未解锁。`
  - 人工临时任务：`人工临时生产任务已跳过提示词流程，不能保存任务提示词。`
  - 已提交・审核中：`当前任务正在审核，不能保存或重新生成提示词。`
  - 已完成：`已完成任务不能保存或重新生成提示词；如需换版，请先由导演发起返工。`

### POST /api/tasks/{task_id}/prompt-jobs（202，P4e-6 新增）

> 既定契约 `create_task_prompt_job`：生成任务提示词并后台执行（运行落库后立即入队，返回 AgentRunRead）。
> 实现：`internal/service/tasks_prompt_jobs.go`（服务）+ `internal/repository/tasks_prompt_jobs.go`
> （引用/指纹/分集上下文）+ `internal/service/task_prompt_context.go`（asset_task 生产上下文，
> 对齐 `task_production_context` + `scope_character_production_context`）+ `internal/productionbrief`
> （ResolvedProductionBrief.v1 / BuildAgentExecutionContext）。
> 契约测试：`internal/api/task_prompt_jobs_contract_test.go`（守卫阶梯逐字 + 快乐路径 + storyboard 分支 + 分集上下文 400）。

- Query：`?step=keyframe|video`（仅 `storyboard_shot` 需要）。
- 守卫阶梯（detail 逐字）：
  - 任务不存在 / 无更新权限 → 404 `Task not found` / 403 `Task permission denied`。
  - `assertTaskPromptEditable`：锁定 → `{前置} 尚未完成，当前任务暂未解锁。`；审核中/已提交 →
    `当前任务正在审核，不能保存或重新生成提示词。`；已完成 → 提示词节上线一致文案。
  - 人工临时任务 → `人工临时生产任务已跳过提示词流程，不能运行提示词 Agent。`
  - `storyboard_shot` 缺/非法 step → `分镜任务需指定 step=keyframe 或 step=video`
  - `storyboard_shot` step=video 无 primary_master keyframe → `关键帧尚未审核定版，视频提示词暂不能生成。`
  - `image_to_video` 前置依赖任务（`depends_on_task_id`）非 completed → `关键帧任务尚未完成，视频任务暂未解锁。`
  - 非可提示词类型 → `Task type does not support prompt generation`
  - 资产任务命中专用 Agent 但缺 `production_context.schema_version` → `资产任务缺少专用生产上下文，无法生成资产 Prompt`
  - 分集作用域任务执行上下文构建失败 → `任务制作上下文不完整：{err}`（缺 production_brief /
    episode_production_brief / 非 16:9 交付比例 / 未知风格等，detail 逐字透传）。
- 类型 → Agent/技能映射：`text_to_image|asset` → `text_to_image_prompt`+`text-to-image-prompt`；
  `image_to_video` → `image_to_video_prompt`+`image-to-video-prompt`；`storyboard_shot` 按 step 派生；
  `asset|text_to_image` 且 `asset_type∈{character,scene,prop}` → 专用 element 设计 Agent
  （`character_design_prompt|scene_design_prompt|prop_design_prompt` + `*-design-prompt` skill），
  此时 `task_type` 覆盖为 asset_type、`output_spec` 未填时按 `task_variant`。
- 输入契约（`input_json` 顶层合并 execution context，仅分集任务有）：
  `task_id / skill / step / context_fingerprint / storyboard_id / task_type / output_spec / description /
  storyboard / assets[] / asset / production_context / agent_reminders / keyframe_reference /
  production_references / style_guide{resolved_style,cultural_origin,global_visual_constraints} /
  resolved_production_brief / duration`。
- 指纹 `context_fingerprint`：对齐 `task_prompt_context_fingerprint`——references 排序 key
  `(task_id, step, submission_id)`、masters 排序 key `(step, submission_id)`、`asset_snapshot or {}`、
  `resolved_production_brief or {}`、项目前缀缺省 `"RF"`，SHA-256(content)。
- `keyframe_reference`：`storyboard_shot` video → 本任务 `step=keyframe` 的 primary_master submission；
  `image_to_video` → 依赖任务的 `file_type=image` primary_master submission（`{task_id, submission_id, file_path}`；
  submissions 升序加载，匹配取倒序首个）。
- op-log：登记 `agent_run_created`（target_type=`agent_run`），detail=`{task_id, agent_type, status}`
  （与 agents 路径 detail 相比多 task_id，对齐既定实现的非正式 job 与 prompt-jobs 差异登记）。

## 候选登记（submissions）

### POST /api/tasks/{task_id}/submissions（201）

- 请求：`file_path`、`file_type`、`prompt_text`/`original_prompt_text` 等；草稿 `draft` 状态。
- `submissionStep` 映射（按 task_type + 是否 storyboard 绑定）：
  - `audio` → `audio`
  - `storyboard_shot` → keyframe/video（否则 400）
  - `text_to_image` → 有 storyboard `keyframe`、无则 `result`
  - `image_to_video` / `video_generation` → 有 storyboard `video`、无则 `result`
  - 其余默认 `result`

### PATCH /api/tasks/{task_id}/submissions/{submission_id}（编辑元数据）

- 守卫（detail 逐字）：`只有未提交草稿或已驳回成果可以编辑说明。` / `已归档或已作废候选不能编辑说明。`

### DELETE /api/tasks/{task_id}/submissions/{submission_id}（移除草稿）

- 200 `{"archived": "{submission_id}"}`。
- 守卫（detail 逐字）：`只有未提交草稿或已驳回成果可以移除；待审核和已定版成果必须保留。`

### PATCH /api/tasks/{task_id}/submissions/{submission_id}/archive（导演归档）

- 200 `{"archived": {bool}}`；导演/admin 权限。

## Submit / Review（产出状态机）

### POST /api/tasks/{task_id}/submit

- 请求：`{request_id?, step?}`。`request_id` 非空必须为合法 UUID（handler 校验，否则 422），存 `task_submission_batches.submit_request_id`。
- 幂等：`uuid5(NAMESPACE_URL, "task-submit:{request_id}:{task_id}:{step}")`；同 key 重放返回既有结果。
- 守卫（detail 逐字）：
  - `请先上传至少一个候选成果。` / `当前批次没有可提交的候选成果。`
  - `当前任务状态不能重复提交。`
  - `提交请求标识已用于其他任务或生产步骤。`（idempotency key 全局唯一）
  - 分镜前置资产未齐：`该场景所需资产尚未全部完成，分镜任务暂未解锁，不能提交。`
- 成功后任务 → `reviewing`。

### POST /api/tasks/{task_id}/submission-batches/{batch_id}/review

- 请求：`decision=approve|rework`、`request_id?`（UUID）、`selected?` + `primary?`（approve 时）、`comment?`。
- `approve`：批次 → `approved`，submissions 按 selected+primary 落 `is_selected`/`is_primary`，物化 AssetVersion（主/备用母版投影）；发通知 `成果已审核定版`。若变更 A 身份主母版 → B-E 失效提醒 `A 身份母版已变更，当前 B-E 成果已失效，请重新生产并提交。`
- `rework`：批次 → `rework`，任务 → `rejected`，追加 `task_approval_reopened` 审计，需填原因。
- 守卫（detail 逐字）：`审批人不能审核自己提交的成果。` / `请根据审核意见重新提交候选成果。`（approve 前必须有 rework 结论时）

### POST /api/tasks/submission-batches/bulk-submit / bulk-review

- `request_id` 必填且必须为合法 UUID（bulk 幂等 key + handler 422）。
- bulk key：`task-submit:{request_id}:{task_id}:{step}` / `task-review:{request_id}:{task_id}:{batch_id}`。
- 守卫（detail 逐字）：
  - `批量提交不能包含重复任务。` / `批量审核不能包含重复任务。`
  - 多任务且含 A 身份变体：`人物 A 身份母版必须独立提交，不能与 B-E 合并操作。`
- 单事务内整批提交/审核；重复任务条目 400。

### PATCH /api/tasks/{task_id}/primary-submission（导演指定主母版）

- 请求：`submission_id` 必填；权限要求 director/admin（或对齐既定契约的组合）。
- 200 返回 `TaskView`；物化/切换 current AssetVersion。

## 工作台

### GET /api/workspace/tasks

- 非 director/admin 强制以自身为 assignee（忽略 `assignee_id` query）；返回 `{stats, groups}`：
  - `stats`: `todo` / `completed` / `overdue` / `completion_rate`
  - `groups`: `{todo: TaskView[], completed: TaskView[]}`

### GET /api/workspace/reviews

- 非 director/admin → 403 `Project review permission required`（既定契约逐字）。
- director/admin：跨项目待审任务（submitted/reviewing/rejected/completed 且有 submitted/approved/rework 批次）。

## 分组路由（/api/projects/{project_id}）

| 路由 | 权限 | 语义 |
|---|---|---|
| GET `/storyboards` | `_can_access_project`（含可见任务回退） | 分镜列表，`?episode_id=...` 过滤（按 episode_no 解析，分集不存在 → 404）；非导演按可见任务过滤 |
| GET `/board` | 同上 | 生产看板 `ProductionBoardRow[]`（storyboard + tasks + submissions，按分镜聚合，导演全量） |
| GET `/scene-gating` | 同上 | `SceneGatingRow[]`（scene_code/scene_name/required/pending/locked） |
| POST `/storyboard-video-tasks` | 同上 | `{project_id, episode_code, scene_code, created_tasks, task_count}`；已有 img2video 任务则幂等跳过（created_tasks=0）；同一 scene 维度不重复创建 |
| POST `/task-assignments` | **director/admin**（middleware） | 批量分配/改派：scope 未知 → 400 `未知的分配范围: {scope}`；executor 无效 → 400 `执行人无效、已停用或不是可分配的制作人员。`；改派缺原因 → 400 `批量改派必须填写改派原因。`；返回 `BulkAssignResult{assigned, reassigned, scope, key, skipped, skipped_by_status, completed_assignments}` |

## 通知（reassignment 保留）

P3g 通知中心整体延后，但任务改派/审核定版通知在事务内落库（`notifications` 表 `is_read=false` 显式写入，对齐既定 ORM 语义 `default=False`；该列无 DB server default）。

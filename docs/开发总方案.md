## 1. 目标形态

根目录统一入口 + 两个独立仓库（前端 / 后端）。

```
/Users/chenjiaming/code/cnjm/cine-forge/     ← 工作区（根入口 + 两个仓库）
├── README.md                  ← 统一入口（跳转两仓库 + docs + skill）
```

**核心原则**
- 产品名统一为 **CineForge**；仓库/包/DB/域名命名规范见 §2。
- 前端样式 100% 不变，只允许四点逻辑适配（见 §5.2）；后端为 Go 单体。
- Python 仅保留「五步拆解 Agent 编排」最小作用域，作为 `agent/` 子模块被 Go 调用。
- 数据库合并单库；云效 CICD 编译产物直接部署 ECS。

## 5. 前端 cineforge-h5

### 5.1 内容
前端全量源码落地（`src/features/**`、`src/hooks/**`、`src/shared/**`、样式、assets），作为 CineForge 前端唯一代码集。**样式/页面结构/交互一概不动**。

### 5.2 允许的四处适配
1. API 寻址：新增 `.env.development` / `.env.production` → `VITE_API_BASE=https://cine-forge-server.cnjm.top` 等；
2. token 交互：access/tapcanvas/platform 三个 token 存储与携带方式不变，仅目标地址变化；
3. SSE/长连接：`run-events` 跟随 API 域名，CORS 由 Go 放行；
4. 移除 nginx/反代：OSS 静态托管，无 nginx 托管段。
   **样式文件不动。**

### 5.3 代码规范
TS 严格模式 + ESLint + Prettier；分层 `pages/features/hooks/shared/types/api`；页面禁止写网络层；沿用 React 19 无全局状态库；损坏/未完成页面留占位（路由+页壳+TODO）。

### 5.4 打包与 OSS
`npm run build` → `dist/` 自行传 OSS；README 含 OSS 静态托管/SPA rewrite 配置。

## 6. 后端 cineforge-server

### 6.1 进程拓扑（ECS 双产物）

```
┌───────────────────────────────────────────────┐
│ cineforge-server（ECS）                        │
│  [Go 单体 binary]  HTTP :8080 / gRPC :8090     │
│    internal/identity 登录/用户/权限/Casbin      │
│    internal/project 项目/分集/剧本/拆解元数据    │
│    internal/task    任务/提交/审核/母版/rework   │
│    internal/asset   资产库/文件/MinIO           │
│    internal/notify  通知/操作日志               │
│    internal/dashboard 生产看板                  │
│    internal/agent-client      ──HTTP→ agent   │
│    internal/canvas           画布内部包         │
│  [agent 子模块（Python）]                       │
│    五步拆解编排 + Hermes 调用 + Celery          │
└───────────────────────────────────────────────┘
```

### 6.2 数据库 → 单库 `cineforge`
- 身份：`users` 为唯一身份主，平台用户与画布用户投影并入；`sys_role` + `sys_casbin_rule` 保留作授权（Casbin）。
- 业务（users/permissions/projects/scripts/storyboards/assets/tasks/submissions/files…）、画布（`flows` 等，版本在 flows 字段上）、通知（notifications/operation_logs）全部统一入库。
- **移除**：`integration_sync_outbox`（单进程不需跨服务投影）、画布侧重名投影表。
- 各域表映射关系与逐表决策见 `docs/后端/单库schema映射.md`（已确认），业务语义不改。
- 迁移用 goose，版本从 1 开始；禁止启动建表。

### 6.3 Go 代码规范
分层 `cmd / internal/api / internal/service / internal/repository / internal/model`；HTTP 框架 **gin**；gRPC 仅画布/agent 内部通道；zap 日志；config.yaml + env 双通道。

## 8. 云效 CICD（5）

- 双产物流水线（Go binary + Python agent）：
  1. checkout cineforge-server
  2. Go `go build` → Linux amd64
  3. agent `pip install + venv 打包`
  4. 上传产物到产物库
  5. ECS `deploy.sh`：停旧 → 换新 → systemd 拉起 → `/ready` 健康检查
- systemd：`cineforge-server.service`、`cineforge-agent.service`。
- 前端 OSS 部署不进 CICD（自行推 OSS）。
- 云效/ECS/AccessKey 等具体值以 `config.yaml`/`.env.example` 占位，填实际值。
- 配套文档 `docs/cicd/云效发布说明.md`（流水线配置、变量、上线回滚）。

## 10. 风险

- Agent 执行链路最重（P4）；token 三件套（access/tapcanvas/platform）由 Go 统一签发，算法与互操作常量不变；
- SSE/长连接跨 OSS 静态页需 Go CORS 配置到位（P1 前置）；
- 众多库→单库破坏性变更，白名单环境预演，不直接动生产。

## 11. 明确不做

- 不改前端视觉；不新增业务功能（后续单独提）；不做多租户/HA。

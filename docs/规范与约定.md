# CineForge · 代码规范与全局约定

> 各仓库 CLAUDE.md 是细粒度规范；本文是总览与红线。

## 红线（不可协商）

1. **前端视觉 100% 不变**：样式 / 页面结构 / 交互不改；只允许「env/API 寻址、token 交互、SSE 域名、删 nginx」四处逻辑点被点名调整。
2. **后端 schema 只走 goose**：禁止启动建表、禁止手工 DDL，禁止改历史 migration 文件。
3. **配置双通道**：`config.yaml` + 环境变量；域名/库名/bucket/密钥全是配置项，改配置不改代码。
4. **确定性后台不交给模型**：权限、版本号、任务创建、时长/引用硬校验、文件登记、审核状态由 Go 后台负责。
5. **四层数据链不动摇**：`agent_runs 原始 → 归一化 → 人工 final → 下游`；前端禁止直读 Agent 原始 JSON。

## 前端（cineforge-h5）

- 分层：`pages / features / hooks / shared / types / api`；页面禁止写网络层（统一走 hooks）。
- React 19，无全局状态库；沿用 `useCineForgeApp` 编排。
- TS 严格模式 + ESLint + Prettier；构建 `npm run build` → `dist/` 推 OSS。

## 后端（cineforge-server）

- Go 分层：`cmd / internal/{api,service,repository,model}`；HTTP 框架 gin；zap 日志。
- 单库 `cineforge`（PostgreSQL），goose 迁移版本从 1 开始。
- Python `agent/` 子模块只承载五步拆解 Agent 编排 + Hermes 调用；Go 经 HTTP/gRPC 调用。
- 字段变更顺序：后端 schema/归一化/测试 → 前端 types/转换函数 → 页面。

## 智能体（skill）

全局 skill 固定于 `~/.claude/skills/`：

| skill                  | 用途                       |
| ---------------------- | -------------------------- |
| `cineforge-home`       | 导航统一入口与当前阶段     |
| `cineforge-docs`       | 写需求/进度/方案文档的规范 |
| `cineforge-code-style` | 前后端分层与红线速查       |

## 提交纪律

- 有歧义先问，不擅自做主（用户明确要求）。
- 单仓库统一提交（h5 与 server 同仓，一次提交可跨目录）。
- 提交消息只描述改动本身，不附加自动生成的协作者署名尾部
- 不通过时保持红色待办清单在 `docs/进度.md`。
